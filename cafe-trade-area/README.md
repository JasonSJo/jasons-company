# 카페 프랜차이즈 상권 조사·분석 시스템

출점 후보지의 **상권을 점수화하고, 매출·손익·투자회수를 추정해, 출점 여부를 심의**하는
자산 세트입니다. 파이썬 CLI 파이프라인과 브라우저 콘솔 두 가지 얼굴을 갖지만
**모델은 하나**입니다 — 같은 후보지를 넣으면 어디서 돌리든 같은 숫자가 나옵니다.

```
cafe-trade-area/
├── QUICKSTART.md            # ★ 후보지 수집부터 출점 심의까지 순서대로
├── analysis/                # 파이썬 자동화 파이프라인
│   ├── common.py            #   ★ 모델 본체 — 점수·매출·손익 공식의 단일 원천
│   ├── collect_pois.py      #   반경 내 경쟁/시설 POI 수집 (dry-run 무료 / --live 카카오 API)
│   ├── score_sites.py       #   후보지 100점 채점 → 순위표
│   ├── estimate_revenue.py  #   매출·손익 시뮬 + 민감도(±20%)
│   ├── build_report.py      #   후보지별 제출용 상권조사 리포트
│   ├── run_all.sh           #   ★ 위 넷을 한 번에
│   └── tests/               #   모델 단위 테스트 + 파이썬↔웹앱 대조 테스트
└── app/                     # 상권 분석 콘솔 (웹앱, 설치 불필요)
    ├── index.html           #   그냥 열면 동작 · 데이터는 브라우저에만 저장
    └── js/model.js          #   common.py 의 1:1 포팅
```

## 무엇을 계산하나

### 1) 상권 점수 (100점)

| 항목 | 배점 | 보는 것 |
|---|---:|---|
| 배후수요 | 30 | 주거·직장인구, 아파트 세대, 대학·학원, 오피스빌딩 |
| 유동인구 | 25 | 일평균 유동 + 역 승하차(0.3 가중) |
| 경쟁 | 20 | 카페 1개당 배후인구, 동일포지션 브랜드 수, 자사점 자기잠식 |
| 접근성 | 15 | 역 도보시간, 코너, 1층, 전면 길이, 주차 |
| 비용 | 10 | 평당 임대료 |

등급: **A** 80+ 즉시 출점 검토 · **B** 65+ 조건부 추천 · **C** 50+ 보류 · **D** 부적합

### 2) 매출 추정 — 「상권 총 카페수요 × 자사 점유율」

유동인구에 유입률을 한 번 곱하는 흔한 방식은 **유동에 이미 포함된 직장·주거 인구를
중복 계산**해 매출을 크게 부풀립니다. 그래서 두 단계로 나눕니다.

```
상권 하루 카페 이용객 = 유동인구×4.5% + 주거인구×5% + 직장인구×12%
자사 점유율          = (1 / 반경 내 카페수+1) × 입지배수(0.70~1.80, 접근성 반영), 상한 25%
하루 객수            = 상권수요 × 점유율      ← 좌석 처리능력으로 매장 이용객에 상한
월 매출              = 하루 객수 × 객단가 × 영업일수
```

### 3) 손익 · 투자회수

- **변동비** 재료비 + 카드수수료 + 로열티 + 광고분담금
- **인건비는 고정비가 아니다** — 매출이 오르면 사람을 더 쓴다. `max(최소인건비, 매출×인건비율)`
- **BEP** 도 그래서 두 구간(최소인건비 구간 / 인건비율 구간)으로 나눠 푼다
- **투자회수기간** 은 보증금을 뺀 매몰투자 기준 (보증금은 폐점 시 돌려받는 돈)

### 4) 심의 결론

점수가 높아도 **손익이 안 나오면 반려**입니다. `출점 추천 / 조건부 추천 / 보류 / 반려`
네 결론과 리스크 목록(BEP 미달, 회수 36개월 초과, 자기잠식, 동일포지션 과밀 등)을 함께 냅니다.

## 쓰는 법

```bash
cd cafe-trade-area/analysis
pip install -r requirements.txt          # PyYAML 하나뿐

./run_all.sh                             # 예시 데이터로 전 과정 확인 (무료·네트워크 없음)
./run_all.sh --sites 내후보지.csv         # 내 데이터로
./run_all.sh --live --sites 내후보지.csv  # 실제 POI 수집까지 (KAKAO_REST_KEY 필요)
```

결과는 `analysis/output/` 에 쌓입니다.

- `상권_후보지_순위.md` — 순위·등급·추정 손익 한눈에
- `손익_시뮬레이션.md` — 손익계산서 + 손익분기 역산 + 민감도
- `reports/상권조사_*.md` — 후보지별 제출용 리포트

**터미널 없이 하려면** `app/index.html` 을 열면 됩니다. 같은 계산을 브라우저에서 하고,
결과를 CLI 입력 형식 그대로 내보냅니다. → [app/README.md](app/README.md)

## 비용

| 하는 일 | 비용 |
|---|---|
| 점수화·매출추정·손익·리포트·웹앱 전부 | **무료** (규칙 기반, 네트워크 불필요) |
| `collect_pois.py --live` | 카카오 로컬 API — 개인 개발자 무료 쿼터 내 무료, 초과 시 과금 |

`--live` 를 붙이지 않으면 어떤 외부 호출도 하지 않습니다.

## 자동화되는 것 / 사람이 해야 하는 것

**자동:** 후보지 채점·순위, 경쟁 POI 수집, 매출·손익 추정, 민감도, 리포트 생성

**사람:** 현장 실사(주차·동선·간판 가시성·실제 유동 관찰) · 임대조건 협상 ·
가맹 계약과 대금 · **최종 출점 결정**

> 이 시스템의 숫자는 공개 지표와 규칙 기반 모델에 의한 **추정치**이며 실제 매출을 보장하지
> 않습니다. 후보지를 20곳에서 3곳으로 줄이는 데 쓰고, 그 3곳은 발로 확인하십시오.

## 모델이 갈라지지 않게 하는 장치

`analysis/common.py`(파이썬)와 `app/js/model.js`(자바스크립트)는 같은 공식의 두 구현입니다.
한쪽만 고치면 "콘솔에서 본 점수와 CLI 리포트가 다른" 사고가 납니다. 그래서 테스트가 있습니다.

```bash
cd analysis && python3 -m unittest discover -s tests -t .
```

- `test_model.py` — 점수 상·하한, BEP 가 진짜 손익분기인지, 적자 후보지 처리 등
- `test_parity.py` — 예시 데이터 + **경계값 픽스처**로 두 구현의 모든 수치를 대조하고,
  생성되는 리포트 마크다운이 **글자 단위로 같은지**까지 확인
- `test_demo_sync.py` — 콘솔 데모 데이터가 예시 CSV·YAML 과 같은지

반올림 규칙(0.5 는 절대값이 커지는 쪽)도 양쪽에 같은 구현으로 맞춰 두었습니다.
파이썬 기본 `round()` 는 은행가 반올림이라 그대로 두면 점수가 0.1 씩 어긋납니다.
